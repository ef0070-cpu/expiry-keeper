### R-2 [필수] 세트 C의 CSS 예시 박스 지시가 실제 통계 화면과 다름 (앱에 없는 요소)
- 위치: instagram-threads.md 97행 "CSS 예시 박스: 월 선택 + 버림/소진 막대 2개, 숫자 없음"
- 근거: BRIEF 2장 "앱에 있는 요소만 그린다". 실제 화면은 "월 선택"이 아니라 **월별 행마다 '소진 n · 폐기 n' 글자와 소진/폐기 비율 가로 막대 한 줄**이다(`stats.tsx:92-104`), 막대는 2개가 아니다. 모양이 다른 예시를 "앱 화면"처럼 쓰면 오인 소지가 있다. 또 막대 길이가 한쪽으로 크면 "폐기가 많다/줄었다"는 암시가 된다.
- 현재 문구 → 수정 제안
  - 97행 "CSS 예시 박스: 월 선택 + 버림/소진 막대 2개, 숫자 없음, 라벨 …" → "CSS 예시 박스: 스토어판 통계 화면 확인 뒤 같은 구성(월 이름 행 + '소진 · 폐기' 글자 + 소진/폐기 가로 막대 한 줄)으로 그린다. 두 값은 비슷한 비율로 두어 좋아졌다·나빠졌다는 인상을 주지 않는다. 라벨 '예시 화면 · 실제와 다를 수 있어요'는 카드 위쪽에 크고 진하게. 캡처가 오면 교체."
  - 스토어판 통계 화면 모양 확인은 이미 BRIEF 4장 체크 항목이므로 그것을 게시 전 필수로 유지.

## 권장

### S-1 [권장] "날짜는 입력해 둔 내용을 기준으로 보여 드려요" 단서 — 어느 세트에 넣을지
- 판단: **A와 C에는 넣지 않아도 된다. B에는 유지하되 범위를 넓히는 것을 권장한다.**
  - A(검색발주): 날짜·기록 주장이 없어서 불필요.
  - C(월별 기록): 이미 본문이 "버린 것과 다 쓴 것을 **기록해 두고**"로 사용자 입력 전제를 말한다. 필수 아님. 넣고 싶으면 선택 문구 "기록해 둔 내용을 기준으로 보여 드려요."
  - B: 날짜뿐 아니라 "냉동고에 뭐가 남았는지"를 앱이 아는 것처럼 읽힐 수 있다. 목록은 사용자가 등록하고 소진·폐기로 정리한 만큼만 맞는다. 단서가 날짜만 덮고 있다.
- 현재 문구 → 수정 제안
  - 56행, 73행 "날짜는 입력해 둔 내용을 기준으로 보여 드려요." → "목록과 날짜는 등록해 둔 내용을 기준으로 보여 드려요."
