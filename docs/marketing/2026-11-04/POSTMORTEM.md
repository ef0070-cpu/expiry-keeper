# 11/04 홍보 이미지 사고 보고 및 문책

작성: 2026-11-04 밤 (리더) / 근거: 사장님 지적, 11/04 폴더의 BRIEF·REVIEW·REVIEW-BLOG·design 파일, `.claude/agents/ek-design.md`
성격: 개인 징계가 아니라 **책임 소재를 밝히고 재발을 막는 기록**이다. 에이전트에게 벌을 주는 기능은 없으므로 정의서·규칙·심사 기준을 고치는 것으로 조치한다.

## 1. 사장님 지적 (4가지)
1. 이미지가 **앱 화면과 동떨어졌다.**
2. **디자인 수준이 너무 낮다.**
3. **내용이 틀렸다.**
4. 이 앱의 **주 타깃은 무인 아이스크림 할인점 점주**이고 그렇게 설계했는데, **과자를 발주하는 그림**이 나왔다. 이해가 안 된다.

지적은 모두 사실이다. 실제 앱 스크린샷(`store-assets/screenshots/`)과 비교하면, 앱은 손글씨체 글꼴·빨간 포인트·흰 카드·'검색발주/빠른발주' 탭·냉동고 구역 칩('600바-1')·'+ 상품 진열하기' 버튼이 있는데 우리가 만든 카드·사진은 단순 줄과 박스로 그린 가짜 화면에 "과자 A·B·C·음료 D·냉동 상품 B"가 들어 있었다.

## 3. 이미 나간 것 (영향)
- 11/04 21:25~21:27에 게시한 **인스타 카드 13장·스레드 이미지 4장**에 같은 문제(가짜 앱 화면, 과자 예시)가 있다. 카드 이미지는 게시 후 교체할 수 없다.
- 블로그는 아직 올라가지 않았다(이미지 신규 제작 중).
- 처리 방안은 사장님 결정이다: ① 그대로 두고 다음 묶음부터 새 규칙 적용 ② 6건을 내리고 새 이미지로 재게시.

## 4. 재발 방지 (조치 완료)
- `docs/marketing/BRAND-VOICE.md` **7장 신설**: 주 타깃(아이스크림 할인점 점주), 앱 화면 실제 일치(실제 캡처 우선, 없으면 소스 재현 + `design/SOURCE-MAP.md` 근거표), 앱 글자 용어 우선, "CSS 예시 화면으로 때우기" 금지, 디자인 수준 기준(실제 스크린샷과 나란히 비교), 심사 항목.
- `ek-design.md`: "캡처 없으니 CSS로"라는 지시를 받으면 **따르지 않고 이의를 제기**한다는 규칙 추가.
- `ek-promo-lead.md`: **8번 채점 항목 "타깃·앱 일치"** 추가. 실제 앱과 나란히 비교한 결과를 장마다 적어야 하고, 4점 미만이면 다른 항목이 높아도 반려.
- 리더 규칙: 캡처가 없을 때 "대충 그린 예시 화면"을 지시하지 않는다. 캡처를 요청하거나 소스 재현을 지시한다.
- 신규 이미지 4장은 이 규칙으로 처음부터 다시 만든다(`blog-images-v2/`).
